**What this proposes**

The app is a single 488-line `index.html` that works. This proposal rebuilds it as plain ES modules with no build step: config, calculator, countries, provider, ui and main. The logic modules contain no DOM code, so Node's built-in test runner can test them, and CI runs those tests on every PR into `develop` and `main`. The dataset becomes one CSV, generated by a committed Python script from UN World Population Prospects 2024, with source and year stored on every row. Lookup falls back in four steps: country gender value, then country total, then parent region, then world. The IP-geolocation call is replaced by a guess from the browser locale, so the page makes no third-party requests. The ticker stays but is reworded. Light mode is fixed for WCAG AA contrast. The license becomes PolyForm Strict, and the README, `llms.txt`, JSON-LD and spec are updated to describe what actually ships.

**How the existing system works, per this document**

A single `index.html` holds the markup, CSS, an inline closure of JavaScript and an embedded copy of a 192-country CSV. GitHub Pages serves it from the root of `main`. On first visit the page calls `ipapi.co` to guess the country. It loads the data from the fetched CSV, or from the embedded copy if the fetch fails, and caches it in Local Storage for 24 hours. It computes life expectancy minus age in several units and shows a live seconds ticker labelled as a countdown. An unknown country silently falls back to the US figure under a "default-global" label. The README describes a React/TypeScript app whose files are all 0 bytes. There are no tests and no LICENSE file, and the license and URL statements contradict each other.

Both paraphrases came easily. No section is impossible to restate.

**Findings**

1. **Severity: 🟡 Major**
   **Scope:** lines 309–313 and 491–493 (button contrast in light mode).
   **Issue:** The plan sets button text to `color: var(--bg)` (#0f1214, "above 7:1"). Line 491 also gives light mode its own value for `--bg`, and `index.html:99` uses `--bg` as the page background. In light mode, `--bg` will be a light colour, so the button text becomes light-on-teal. That is the same failure G6 is meant to fix. Either the plan needs a separate token, such as `--on-accent`, or it should say that `--bg` stays dark. As written, the parts do not connect.

2. **Severity: 🟡 Major**
   **Scope:** lines 257–265, 314–316, 429–430, 518–521, 525–527 (fallback steps 2 and 3).
   **Issue:**
   - The build script exits non-zero if any country row lacks a finite `male`, `female` or `total`.
   - `tests/dataset.test.js` enforces the same rule.
   - So the "country-total" and "region" fallbacks, and the footnote example "Using the Northern America average", can never trigger with the shipped data.

   The document never says why they are kept: to satisfy the spec, or to guard against future data. A reader cannot tell whether these are live behaviour or dead code. One sentence would fix this.

3. **Severity: 🟡 Major**
   **Scope:** line 156 (CUJ 2) vs lines 248–250 and 408 (data freshness).
   **Issue:** CUJ 2 promises new data "without waiting for a cache to expire". The Technical Plan says new data arrives "within the Pages cache lifetime". That is still a cache expiry, and its length is never stated. A reader can't tell whether CUJ 2 is met. The document should state the lifetime it relies on (the GitHub Pages default) or reword CUJ 2.

4. **Severity: 🟡 Major**

   The reader cannot work out which of the 20 entries actually go in the rename table. That leaves the script under-specified, even though the Technical Plan says the table is "short" and "fixed".
